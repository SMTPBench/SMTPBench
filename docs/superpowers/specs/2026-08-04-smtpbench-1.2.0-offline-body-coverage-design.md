# SMTPBench 1.2.0 — Offline EML, Body Prefix & Coverage Gate Design

**Date:** 2026-08-04
**Status:** Approved for planning
**Version target:** 1.2.0 (folded into the unmerged 1.2.0 branch/PR #10 — no version bump)

## Goal

Add three capabilities to SMTPBench:

1. **Coverage gate** — enforce a combined (unit + integration) code-coverage floor in CI, with per-suite numbers reported for visibility but not gated individually.
2. **Body-prefix mode** (`body_text_dir=PATH`) — optionally prepend a randomly chosen text excerpt from a folder to each message body, keeping subject and the rest of the body as-is.
3. **Offline EML mode** (`eml_out_dir=PATH`) — instead of sending over SMTP, write each message to a folder as an `.eml` file named by the SHA-256 of its bytes. Fully offline: no DNS/MX lookup, no banner check.

All three are additive and independently testable. None changes existing default behavior. They fold into the unmerged 1.2.0 branch (PR #10); no version bump.

## Global Constraints

- **Version stays 1.2.0 (no bump).** These features fold into the existing unmerged 1.2.0 branch (PR #10). `pyproject.toml` `version` and `smtpbench/__init__.py` `__version__` remain `1.2.0`; the new features are added to the existing `## [1.2.0]` entry in `CHANGELOG.md` rather than a new version section. `deploy.sh` still aborts on any version mismatch.
- **Content/metadata split (invariant):** raw payload bytes/text flow only into the MIME message. Only *metadata* reaches logs, summary JSON, debug output, or terminal. This already governs attachments (`attachment_metadata()` whitelist + `log_json()` content-key filter); it now also governs body excerpts (log filename + length, never the excerpt text).
- **Credential redaction (invariant, unchanged):** credentials never reach any log/summary/debug/terminal except the single CLI-credential warning. Summary `config.auth` stays a boolean.
- **Module-global threading model is by design.** New shared state (`body_plan`, `offline_mode`, `eml_out_dir`) follows the existing pattern: module globals mutated under the single `lock`, reset in `tests/conftest.py`'s autouse `reset_globals` fixture (both the before-yield and after-yield blocks).
- **`key=value` argument parsing.** New flags are parsed the same way; presence of the key enables the mode. Booleans compared as strings.
- **Ruff owns lint+format** (`E, F, I, W, UP`, `E501` ignored, line-length 100, py38 target). `docs/` excluded from ruff.
- **Deterministic RNG.** Per-message random choices use the existing seeded generator `random.Random(f"{run_uuid}:{thread_id}:{message_id}")` so a given run is reproducible.

## Feature A — Coverage gate

### Tooling (`pyproject.toml`)

- Add `pytest-cov>=5.0` to the `[project.optional-dependencies] dev` list.
- Add coverage config:

```toml
[tool.coverage.run]
source = ["smtpbench"]
parallel = true      # unit and integration runs write distinct .coverage.* files
omit = ["smtpbench/__main__.py"]   # thin re-export; not meaningfully testable

[tool.coverage.report]
fail_under = <MEASURED>   # set a few points below the measured combined number
show_missing = true
```

`parallel = true` is what makes `coverage combine` across two CI jobs work: each
run writes a uniquely suffixed `.coverage.<host>.<pid>.<rand>` data file rather
than overwriting a single `.coverage`.

### CI (`.github/workflows/pytest.yml`)

- **`unit-tests` job:** run `pytest -v -m "not integration" --cov --cov-report=` (report suppressed here — data only), then upload the `.coverage.*` file as an artifact named `coverage-unit`.
- **`integration-tests` job:** same, `-m "integration"`, artifact `coverage-integration`.
- **New `coverage` job:** `needs: [unit-tests, integration-tests]`. Downloads both artifacts, runs:
  - `coverage combine` (merges the two data files)
  - `coverage report` — **this is the gate**; exits non-zero below `fail_under`.
  - An informational step printing per-suite numbers (run `coverage report` against each artifact separately before combining, or emit them as a summary). This step does **not** gate — it's for visibility so a silent drop in one suite is noticeable.

### `deploy.sh`

- Run unit-only coverage (`pytest -m "not integration" --cov --cov-report=term-missing`) for a fast local signal. Do **not** hard-gate deploy on the combined number — `deploy.sh` cannot run the Docker integration suite, so it can only see the deflated unit-only figure. The authoritative gate lives in CI.

### Threshold determination

Unit-only coverage is ~58% today (the uncovered lines are the threaded send
path, `worker`, `check_smtp_banner`, and `main` — all driven by integration
tests). The combined figure will be materially higher. During implementation,
measure the actual combined number and set `fail_under` a few points below it:
high enough to catch real regressions, with enough slack that an unrelated
refactor moving lines between suites does not trip the build.

### Why not gate suites separately

Coverage is `executed ÷ total-lines-in-file`; the denominator is always all of
`cli.py`, never "the lines this suite should cover." So each suite measured
alone is structurally deflated and does not correspond to a meaningful quality
bar. Two separate thresholds are also brittle: moving a test between the unit
and integration files shifts both numbers and can red-build a change that
improved nothing. The combined union is the honest signal; per-suite numbers
are reported for visibility only.

## Feature B — Body-prefix from text folder (`body_text_dir=PATH`)

### Behavior

When `body_text_dir=PATH` is present, every message body is prefixed with a
randomly chosen text excerpt from that folder. Layout (subject echo + footer
preserved verbatim):

```
<file excerpt text>

Quick test from thread 1 message 1 [<run_uuid>]

--
SMTPBench Load Testing Tool
https://github.com/SMTPBench/SMTPBench
```

Subject header, the subject-echo line, all `X-SMTPBench-*` tracking headers, and
the signature footer are unchanged. Only the excerpt + one blank line are
prepended.

### Corpus loading

`build_body_plan(args)` mirrors the existing attachment-dir corpus loader
(`cli.py:574`):

- If `body_text_dir` absent → return `None` (mode off).
- If path is not a directory → raise (startup error, same handling as attachments).
- Read every regular file (sorted) as UTF-8 with `errors="replace"` (one bad byte
  never crashes the run). Build a corpus of `{"filename": name, "char_len": len(text), "content": text}`.
- Empty/unreadable dir → raise `ValueError` (same contract as `attachment_dir`).
- Returns a small plan object (or dict) holding the corpus.

### Selection & assembly

- New module global `body_plan` (default `None`), set in `main()`, reset in `conftest.py`.
- In `send_email()`, after building the attachment configs with the seeded RNG,
  select the body excerpt with the **same** `rng` so the choice is deterministic
  per message: `body_choice = body_plan.select(rng) if body_plan else None`.
- `create_message()` gains an optional `body_prefix=None` param. When set:
  `body = f"{body_prefix}\n\n{existing_body}"`. When `None`, body is unchanged.

### Logging (content/metadata split)

- Pass log-safe body metadata through the same `log_json` calls as attachments:
  a `body_source` field = `{"filename": ..., "char_len": ...}` (or `None`). The
  excerpt **text** is never logged.
- Summary `config` gains `"body_text_dir": true/false` (boolean — presence of the
  mode, not the path, consistent with how `auth` is a boolean).

## Feature C — Offline EML output (`eml_out_dir=PATH`, fully offline)

### Behavior

When `eml_out_dir=PATH` is present, SMTPBench does not open any SMTP connection.
For each message it would have sent, it serializes the message and writes it to
`{eml_out_dir}/{sha256}.eml`, where `sha256` is the hex digest of the message
bytes. A successful write counts as a success.

### Network bypass

In `main()`, when offline:

- **Skip** `mx_lookup_all()` / `lb_host` resolution — no DNS.
- **Skip** the pre-flight `check_smtp_banner()` and the `[INFO] TLS mode` /
  banner lines.
- Print `[INFO] Offline mode: writing EML to <abs path>` instead.
- `recipient` is still required (it populates the `To:` header) but need not be a
  deliverable address; no MX is looked up for it.
- `mx_hosts` is left empty; the end-of-run "SMTP Hosts Tried" line prints
  `(offline — wrote EML files)` or similar rather than an empty join.

New module global `offline_mode` (bool) and `eml_out_dir` (str/None), both reset
in `conftest.py`.

### Write path

`write_eml(msg, out_dir)`:

```python
raw = msg.as_bytes()
digest = hashlib.sha256(raw).hexdigest()
path = os.path.join(out_dir, f"{digest}.eml")
with open(path, "wb") as f:
    f.write(raw)
return digest
```

- `os.makedirs(eml_out_dir, exist_ok=True)` once at startup.
- Content-addressed naming means identical bytes coalesce to one file (free
  dedup). In practice the `Date` header (`localtime=True`) plus per-message
  thread/message-id headers make collisions between distinct messages
  vanishingly unlikely; identical-content collisions are intentional dedup.

### Send fork

`send_email()` forks at the top:

- **Offline:** build the message (with attachments + body prefix as normal),
  time the `write_eml` call, treat it as a success:
  `record_result(True, write_duration, "file")`. The per-MX bucket is keyed
  `"file"`; latency samples include the write time. **No retry loop** — a local
  write either succeeds or raises; a raised write is recorded as a failure via
  the existing failure path with host `"file"`.
- **Online:** unchanged (`try_send_to_mx_hosts` + retry loop).

Progress bar, counters, rate limiter, journal (N/A offline — journal appends a
recipient, which is meaningless with no send; document that `journal` is ignored
in offline mode), and summary JSON all ride along.

### Composition

Offline mode composes with attachments and `body_text_dir`: the `.eml` written is
exactly the message that would have been sent, including attachments and body
prefix. That fidelity is the point — it lets a user capture-and-inspect without a
live server.

### Summary

- `config` gains `"offline": true/false`.
- `per_mx` shows `{"file": {"sent": N, "failed": M}}` in offline runs.
- `latency_ms` reflects file-write durations.

## Test strategy

**Unit (`tests/test_smtpbench.py`):**
- Body corpus: happy path (loads N files), empty dir raises, missing dir raises, non-UTF-8 file handled via `errors="replace"`.
- Body-prefix assembly: `create_message(..., body_prefix="X")` puts `X\n\n` before the subject-echo line; subject header + footer + tracking headers unchanged; `body_prefix=None` leaves body identical to today.
- Deterministic selection: same `(run_uuid, thread, message)` seed picks the same excerpt.
- `write_eml`: filename equals `sha256(msg.as_bytes())`; identical bytes → same filename (dedup); writes into a tmp dir.
- Offline `send_email` fork: with `offline_mode=True` and a tmp `eml_out_dir`, a call writes exactly one `.eml`, increments `success_count`, records a `"file"` per-MX bucket, and never touches SMTP (assert `smtplib` untouched via mock).
- Summary/config fields: `offline`, `body_text_dir` booleans present and correct.

**Integration (`tests/test_integration.py`):**
- Offline run (`eml_out_dir=<tmp>`, small thread/message counts) writes exactly `threads × messages` `.eml` files, each named `<64-hex>.eml`, each parseable as a MIME message carrying the run UUID header. No Docker mail server needed for this one — it's offline — but it lives with the integration suite since it exercises the full `main()` path end to end.

**Coverage gate:** verified by CI itself (the `coverage` job fails the build below `fail_under`).

## Out of scope

- HTML bodies / multipart-alternative for the excerpt (plain text only).
- Per-recipient or weighted excerpt selection (uniform random only).
- Compressing or batching EML output.
