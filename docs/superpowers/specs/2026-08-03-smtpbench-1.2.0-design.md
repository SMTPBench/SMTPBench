# SMTPBench 1.2.0 — Design

**Date:** 2026-08-03
**Status:** Approved (pending written-spec review)
**Target release:** 1.2.0 (minor), published alongside the marketing site.

## Motivation

A pre-launch review flagged gaps that a cautious mail admin would notice on
first inspection. This release closes them and earns the
`Development Status :: 5 - Production/Stable` classifier:

1. Release cadence — addressed (1.1.1 shipped 2026-08-03); 1.2.0 ships with the site.
2. **No SMTP AUTH** — the #1 gap; most authenticated relays reject unauthenticated submission on 587.
3. **No throughput cap** — `threads × messages` controls volume, not rate; benchmarks aren't comparable across runs.
4. **No summary artifact** — the terminal summary is ephemeral; CI can't assert on it.
5. **No message/attachment size variation** — real mail isn't 200 bytes.
6. **Attachment realism** — a corpus directory sampled at random, with a
   percentage of mail carrying attachments and some carrying multiple.

A latent bug surfaced during design: port 465 is advertised in help/examples,
but the code only ever uses `smtplib.SMTP` + optional `starttls()` — it never
uses `SMTP_SSL`, so implicit-TLS (465) submission does not actually work. This
release fixes that as part of the transport work.

## Scope

In scope for 1.2.0:

| Feature | CLI surface |
| --- | --- |
| SMTP AUTH | `username=` / `password=`, env vars, `.env` |
| TLS modes | `tls_mode=starttls\|ssl\|none`; auto-`ssl` on port 465 |
| Global rate cap | `rate=` (messages/sec, whole-run) |
| Summary artifact | `summary_{timestamp}_{uuid}.json` |
| Attachment size range | `attachment_size=10KB-2MB` |
| Attachment directory | `attachment_dir=`, `attachment_probability=`, `attachment_count=1-3` |
| Classifier bump | `4 - Beta` → `5 - Production/Stable` |

Out of scope: a separate message-*body* size knob (the reviewer's item 5 is
satisfied by the attachment size range — confirmed with the user), rate jitter,
mixing attachment modes, OAuth/XOAUTH2.

## Architecture

The application remains single-file (`smtpbench/cli.py`) with the established
module-global-state-under-lock threading model. New state is added to the
`conftest.py` `reset_globals` autouse fixture. Changes by area:

### 1. Credentials & AUTH

Resolution order (first non-empty wins):

1. CLI `username=` / `password=`
2. Environment `SMTPBENCH_USER` / `SMTPBENCH_PASS`
3. `.env` file, loaded via `python-dotenv` early in `main()`; `dotenv_path=`
   overrides the default (`.env` in cwd). `.env` populates `os.environ` only for
   keys not already set, so real env vars win over the file.

`python-dotenv` is added to `dependencies` in `pyproject.toml`.

If credentials come from the CLI, print one warning line at startup: CLI
arguments are visible in `ps`/`top` and shell history; prefer env vars or `.env`.

AUTH happens in the send path after EHLO (and after STARTTLS when the mode uses
it): call `server.login(user, password)` only when a username is present. Runs
with no credentials remain valid (unauthenticated relays, port 25).

**Redaction invariant:** credentials never appear in any log file, the summary
JSON, debug output, or the terminal beyond the "you passed creds on the CLI"
warning. This extends the existing attachment-`content` stripping discipline.
`smtplib` debug (`set_debuglevel(1)`) *does* print the SASL AUTH exchange to
stderr, and base64 is encoding — not obfuscation — so those payloads are
trivially reversible to the plaintext username/password. To honor the invariant
even under `debug=true`, the send path disables `set_debuglevel` for the
duration of `server.login()` (restoring it afterward) so the AUTH exchange never
reaches the terminal. Tests assert both our own log/summary surfaces and the
smtplib debug surface are free of credential material.

### 2. Transport (`tls_mode`)

New `tls_mode` argument with three values:

- `starttls` (default) — `smtplib.SMTP(...)` then `starttls()`. Today's behavior.
- `ssl` — `smtplib.SMTP_SSL(...)`; no `starttls()`. The currently-missing path.
- `none` — plain `smtplib.SMTP(...)`, no TLS.

If `port == 465` and the user did **not** explicitly set `tls_mode`, default to
`ssl`. Otherwise default to `starttls`.

Back-compat: `use_tls=` is retained as an alias — `use_tls=true` → `starttls`,
`use_tls=false` → `none` — and emits a soft deprecation note pointing at
`tls_mode`. If both `use_tls` and `tls_mode` are supplied, `tls_mode` wins and a
warning is printed.

`check_smtp_banner()`, `try_send_to_mx_hosts()`, and the pre-flight check all
take `tls_mode` instead of the `use_tls` boolean and branch on the three modes.

### 3. Rate limiting

A single shared token-bucket limiter (one module-level instance, its own lock),
created in `main()` when `rate=` is set. Each worker calls `limiter.acquire()`
before each send attempt. `rate=N` caps the whole run at N messages/sec
regardless of thread count, making runs comparable.

Interaction rule: if `rate=` is set together with `delay=` or
`random_delay=`, exit with an error at startup — `rate` is the sole pacing
mechanism. With no `rate=`, pacing behavior is exactly as today.

### 4. Attachments — per-message selection

Today `build_attachment_configs()` returns one config list, built once in
`main()` and shared by every message. Per-message probability, random dir
sampling, and count ranges require per-message selection. The model becomes:

- A single `AttachmentPlan` built once in `main()`, holding the mode and any
  preloaded bytes (dir files read into memory once; static file read once).
- `AttachmentPlan.select_for_message(rng)` returns the attachment config list
  for one message (possibly empty).

Three **mutually exclusive** modes (error if more than one of `attachment_path`,
`attachment_size`, `attachment_dir` is given):

- **`attachment_path`** — one static file per message. Unchanged. Probability
  and count knobs do not apply (documented as an error if combined).
- **`attachment_size`** — synthetic bytes. Accepts a fixed size (`512KB`) **or**
  a range (`10KB-2MB`): per message, pick a size uniformly in `[min, max]`.
  `attachment_probability` (default `1.0`) and `attachment_count` (fixed or
  `A-B` range) apply.
- **`attachment_dir`** — read every regular file in the directory into memory
  once at startup (error if empty/unreadable). Per message: roll
  `attachment_probability`; if it hits, sample `attachment_count` files at random
  (fixed or `A-B` range, capped at the corpus size). Covers none / one / multiple.

**Determinism:** the per-message RNG is seeded from `run_uuid` so a run is
reproducible and the pre-send payload estimate reflects the actual plan. Because
selection is per-message, the startup "estimated total attachment payload"
becomes an **expected value** (`probability × mean_count × mean_size × messages`)
and is labeled "estimated (expected)".

The `content`-stripping rule is preserved end-to-end: raw bytes flow only to
`create_message()`; only metadata (`filename`, `size_bytes`, `mime_type`,
`source`) flows to logs and the summary.

### 5. Summary artifact

Each completed send records its duration (ms), final status, and the MX host
used into an in-memory store guarded by the existing `lock`. At run end, write
`summary_{run_timestamp}_{run_uuid}.json` into `log_dir` alongside the other
logs:

```json
{
  "run_uuid": "…",
  "client_hostname": "…",
  "started_at": "2026-08-03T23:41:00Z",
  "elapsed_seconds": 42.1,
  "config": {
    "threads": 5, "messages": 10, "rate": 100,
    "tls_mode": "starttls", "auth": true, "port": 587
  },
  "totals": {
    "sent": 950, "failed": 50, "retried": 12, "success_rate": 95.0
  },
  "latency_ms": { "p50": 120, "p95": 480, "p99": 900, "max": 1500 },
  "per_mx": {
    "mx1.example.com": { "sent": 900, "failed": 10 },
    "mx2.example.com": { "sent": 50, "failed": 40 }
  }
}
```

Percentiles are computed with `statistics.quantiles` (stdlib — no new
dependency); `latency_ms` is omitted or null when there are zero successful
sends. `config.auth` is a boolean only — never the credentials. The terminal
summary is unchanged; the JSON is purely additive. This makes CI assertions like
"fail the build if p95 > 2s" a one-line `jq`/Python check.

## Data flow (send path, per message)

```
worker loop
  └─ limiter.acquire()                 # only if rate= set
  └─ attachments = plan.select_for_message(rng)   # per-message; may be empty
  └─ msg = create_message(..., attachments)
  └─ send_email(...)                   # retry/backoff unchanged
       └─ try_send_to_mx_hosts(tls_mode, creds)
            └─ connect per tls_mode (SMTP / SMTP_SSL)
            └─ starttls() if mode == starttls
            └─ login(user, pass) if username present
            └─ sendmail(...)
       └─ record duration + status + mx_host into summary store
       └─ log_json(...)                # metadata only; no content, no creds
run end
  └─ write summary_{ts}_{uuid}.json
  └─ print terminal summary (unchanged)
```

## Error handling

- **Conflicting attachment modes** (more than one of path/size/dir) → startup error.
- **`attachment_count` with `attachment_path`** → startup error (only meaningful for size/dir).
- **`rate=` with `delay=`/`random_delay=`** → startup error.
- **`tls_mode` and `use_tls` both set** → `tls_mode` wins, warn.
- **Invalid `tls_mode` value** → startup error listing valid values.
- **Empty/unreadable `attachment_dir`** → startup error.
- **Invalid range** (`min > max`, non-numeric) in `attachment_size`/`attachment_count` → startup error via extended `parse_size`.
- **AUTH failure** at connect → counted as a normal send failure per existing retry/failover logic (a bad password fails every MX host and is logged like any other error, with the credential redacted).

## Testing strategy

Unit (`pytest -m "not integration"`):

- Rate limiter: N acquisitions take ≈ N/rate seconds (tolerance-bounded); no `rate` → no delay.
- `tls_mode` selection: explicit values honored; port 465 auto-selects `ssl`; `use_tls` alias mapping; conflict resolution.
- Credential resolution order (CLI > env > `.env`) and **redaction** (assert secrets never appear in captured log/summary output).
- `attachment_size` range parsing (fixed and `A-B`), `attachment_count` range parsing, `min > max` errors.
- `AttachmentPlan.select_for_message` with a seeded RNG → deterministic, honors probability 0/1 and count ranges; dir sampling never exceeds corpus size.
- Summary percentile math on a known latency vector; empty-success case.
- New globals reset in `conftest.py`.

Integration (`pytest -m integration`, Docker Postfix):

- Authenticated `starttls` submission on 587 succeeds and lands in the mbox for the current run UUID.
- `summary_*.json` is produced, is valid JSON, and its `run_uuid` matches the run.
