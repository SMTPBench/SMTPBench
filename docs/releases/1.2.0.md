# 🚀 SMTPBench 1.2.0 — The Realism Release

**SMTPBench grows up.** This release promotes the project from Beta to
**Production/Stable** and lands the biggest feature drop in its history:
authenticated submission, real TLS transport modes, whole-run rate control,
lifelike message generation, a machine-readable run summary, and a fully
**offline** mode that never touches the network.

If 1.1.x was "send a lot of mail, fast," **1.2.0 is "send the *right* mail,
the *right* way, and prove exactly what happened."**

> ⚠️ SMTPBench sends **real email** to whatever host it resolves. Read the
> warning in the README before pointing it at anything.

---

## ✨ Headline features

### 🔐 SMTP AUTH — authenticated submission, done safely
Pass `username=` / `password=` and SMTPBench logs in before sending.
Credentials resolve in a clear precedence order:

```
CLI args  >  environment (SMTPBENCH_USER / SMTPBENCH_PASS)  >  .env file
```

`.env` support is built in via `python-dotenv` (override the path with
`dotenv_path=`). **Credentials never leak** — they are kept out of every log,
the summary artifact, and terminal output, with a single one-line warning if
you pass them on the command line. Supply only half a credential pair and
SMTPBench **fails fast** with a clear message instead of dying opaquely inside
`smtplib.login` on every send.

```bash
smtpbench recipient=you@example.com port=587 threads=5 messages=100 \
          username=loadtest password=$SMTP_PASS
```

### 🔒 TLS transport modes — 465 finally works
New `tls_mode=starttls|ssl|none` (default `starttls`, auto-upgraded to `ssl`
on port 465). This **fixes implicit-TLS submission on port 465**, which
previously never used `SMTP_SSL` at all. The old `use_tls=` flag still works as
a soft-deprecated alias, so existing scripts keep running.

### 🚦 Whole-run rate cap — one dial for the entire fleet
`rate=` (messages/second) is enforced by a **shared token bucket across every
thread** — not a per-thread guess. Want a steady 200 msg/s regardless of thread
count? Set `rate=200`. It's mutually exclusive with `delay=` / `random_delay=`
so intent is never ambiguous.

### 📎 Attachment realism — stop sending identical 10KB blobs
Three ways to make attachments look like real traffic (mutually exclusive):

- **Size ranges:** `attachment_size=10KB-2MB` — each message rolls a size.
- **Corpus sampling:** `attachment_dir=PATH` draws real files from a directory,
  gated by `attachment_probability=` and `attachment_count=A-B`.
- Per-message selection is **seeded from the run UUID**, so a run is
  reproducible.

### 📝 Body-text prefix — realistic message bodies
`body_text_dir=PATH` prepends a randomly chosen text file from a directory
above the standard body. Subject, tracking headers, and footer are all
preserved. Selection is deterministic per run, and **only the filename and
character length are logged — never the excerpt text.**

### 📴 Offline EML output — generate mail without sending a byte
`eml_out_dir=PATH` writes each composed message to disk as `{sha256}.eml`
instead of sending over SMTP. **Fully offline: no DNS, no MX lookup, no banner
check.** The recipient is used only as a header. Composes with attachments and
`body_text_dir`, and identical message bytes deduplicate to a single file —
perfect for building test corpora or inspecting exactly what SMTPBench would
send.

```bash
smtpbench recipient=probe@example.com port=25 threads=4 messages=1000 \
          eml_out_dir=./corpus
```

### 📇 Address lists from a file — many senders, many recipients
`recipient_file=` / `from_file=` / `journal_file=` each read a
one-address-per-line file (blank lines and `#` comments ignored, **every
address validated**) and pick per message, independently. Control ordering per
field with `*_file_order=random|roundrobin` (default `random`). A `*_file`
overrides — and can't be combined with — its single-value counterpart. Chosen
`from`/`journal` addresses are logged per message; the summary records only
file/count/order **metadata**, never the full list.

### 📊 Summary artifact — every run, machine-readable
Each run drops a `summary_{timestamp}_{uuid}.json` in the log directory with:

- the run **config** (secrets redacted; `auth` is a boolean, address lists are
  metadata only),
- **totals** — sent / failed / retried, plus `success_rate`,
- **latency percentiles** — p50 / p95 / p99 / max (stdlib `statistics`),
- **per-MX** sent/failed breakdown.

Totals now derive from **per-message final outcomes** (consistent with
`per_mx`) instead of counting each retried attempt as a separate failure —
so the numbers finally line up with what actually happened.

## 🛡️ Security hardening

- **Credentials no longer leak under `debug=true`.** `smtplib`'s wire debug is
  disabled for the duration of `server.login()`, so the (base64, trivially
  reversible) SASL AUTH exchange is **never** written to the terminal. The
  design doc's earlier claim that base64 SASL was "obscured" was wrong and has
  been corrected.

## 🔧 Changed & fail-fast behavior

- **Production/Stable.** Development status promoted from Beta.
- **Minimum Python is now 3.9** (matches the `setuptools>=77.0.0` build
  requirement).
- **`attachment_filename` + `attachment_dir` now rejected** — the combination
  was silently ignored (corpus files keep their own names); it's a
  configuration error now.
- **Journal destination fails fast.** `journal=true` with `recipient_file=` and
  no `journal_address=` / `journal_file=` (no single `recipient=` to fall back
  to) now **aborts at startup** instead of silently journaling nowhere. A
  present-but-empty `*_file=` value is likewise rejected rather than treated as
  absent.

## ⬆️ Upgrading from 1.1.x

For most users this is **drop-in** — existing command lines keep working:

- `use_tls=` still works (now an alias for `tls_mode=`). Consider switching to
  `tls_mode=` for clarity, especially on port 465 where implicit TLS now works
  correctly.
- If you pass `username=`/`password=`, make sure you pass **both** — a lone
  half now errors at startup by design.
- If you journal while using `recipient_file=`, set `journal_address=` or
  `journal_file=` — the tool will tell you at startup if it's missing.
- Python **3.9+** is now required.

```bash
pip install --upgrade smtpbench
smtpbench --version
```
