# 🩹 SMTPBench 1.2.1 — Offline Runs Stop Asking for a Port

A small patch release. One user-facing bug fix, newly declared support for
Python 3.13 and 3.14, one file removed from the repository, and a documentation
pass so the shipped help text matches the shipped behavior.

**No behavior changes for online runs.** Nothing here affects how mail is
composed, sent, retried, or logged.

> ⚠️ SMTPBench sends **real email** to whatever host it resolves. Read the
> warning in the README before pointing it at anything.

---

## 🐛 Fixed: `port=` is no longer required in offline mode

An offline run — anything with `eml_out_dir=` — writes `.eml` files to disk and
never opens a connection. It performs no DNS/MX lookup and no banner check. So
requiring `port=` was asking for a value the run could not use anywhere:

```bash
# 1.2.0: refused to start — "Missing required parameter(s): port"
# 1.2.1: works
smtpbench \
    recipient=test@example.com \
    threads=5 \
    messages=20 \
    eml_out_dir=./eml-output
```

The cause was ordering rather than a bad list of required keys: the
required-parameter check ran *before* the code derived whether the run was
offline, so the validator had no way to know. That derivation now happens first,
from a single source of truth.

Details worth knowing:

- `port=` is **still accepted** offline. It is recorded in the run summary and
  ignored, exactly as before.
- When omitted, the summary records `"port": null` — consistent with the
  `"offline": true` it sits beside.
- The missing-parameter error no longer lists `port` for a run that cannot use
  one. Online runs still require it and still fail fast without it.

## 🧹 Removed: `.pypirc.example`

The template only restated the `~/.pypirc` block that `DEPLOYMENT.md` already
inlines, and a checked-in file full of placeholder token lines invites someone
to fill it in and commit it in-repo instead of at `~/.pypirc`.

The two details the doc was missing — the `[distutils] index-servers` block and
TestPyPI's `repository` URL — moved into `DEPLOYMENT.md`. `.gitignore` still
ignores `.pypirc`. Packaging and runtime behavior are unaffected.

---

## 🐍 Python 3.13 and 3.14 are now declared supported

`requires-python = ">=3.9"` already allowed them, and the suite passes on both —
but the PyPI classifiers stopped at 3.12, so anyone reading the package page had
no reason to believe it worked.

Rather than just add two lines to the classifier list, CI's unit-test job now
runs as a matrix across **3.9, 3.10, 3.11, 3.12, 3.13, and 3.14**. A classifier
is a claim; the matrix is the evidence for it. `fail-fast` is off so one bad leg
reports rather than hiding the others.

The integration job stays on 3.11 — it is gated by Docker and a real Postfix
container, not by interpreter version, so fanning it out six ways would buy
nothing. Coverage is still collected from the 3.11 leg only, since every leg
executes the same lines.

Ruff's `target-version` also moved from `py38` to `py39` to match the
`requires-python` floor the project actually declares.

## 📚 Documentation

- `--help`, the README required-parameter table, and the Offline EML Output
  section all record the `port=` exemption. The README's offline example no
  longer passes an unused `port=`.
- `SECURITY.md` lists `1.2.x` as a supported version.
- The README's Requirements section names the interpreter versions CI actually
  exercises, instead of only stating a floor.
- `DEPLOYMENT.md`'s version-bump checklist now names every file that carries
  the version, not just three of them.

## ⬆️ Upgrading from 1.2.0

Drop-in. No command lines change, no flags are deprecated, no defaults move.

```bash
pip install --upgrade smtpbench
smtpbench --version
```
